## Q-005 L2b 較正値の再現プロトコル

- **区分**: blocking
- **出所**: 実装計画書 3.1〜3.3節、6.3節、8章 / design/calibration_results.md 8章 / diagnosis/diagnosis/dryrun.py 212〜225行、298〜304行

**回答**: **基準の意図を明確にする。数値の厳密一致は求めない。**

## Q-012 `higher_is_better=false` の frontier score

- **区分**: blocking
- **出所**: 実装計画書 2.2節、8.1節 / design/endpoint_model.md 2章
- **何が不明か**: Favorable は低い値へ反転する規則があるが、`frontier_relevance` は常に 95 percentile、`endpoint + effect`、`max` と定義されており、低いほど良い Endpoint では逆になる。
- **仮に進めるならどうするか**: 全解析の内部で `oriented_y = y`（higher）または `-y`（lower）へ正規化し、効果量・中央値・95 percentile・`max` を oriented scale で計算する。表示時だけ元の単位と符号へ戻す。
- **その案で進めた場合の影響**: 局所的な変更で済むが、段階1で方向規約を固定しないと全レンズの効果方向とスコアが不整合になる。

**回答**: **承認。方針として段階1で固定する。**

> **全解析を oriented scale（大きいほど良い）で行い、表示時のみ元の単位と符号へ戻す。**

効果量・中央値・95 パーセンタイル・`max` はすべて oriented scale で計算する。これを段階1の規約として明文化し、全レンズがこれに従うこと。

## Q-013 レンズ別 `E_adj` の算出モデル

- **区分**: blocking
- **出所**: 実装計画書 8.1節 / design/candidate_generation.md 4.4節
- **何が不明か**: `MW / cLogP / TPSA / 骨格ダミーを回帰で落とした後に残る効果量` は、化合物単位の L1b/L5、pair 単位の L2a、系列残差の L2b、仮想候補の L4、系列ペアの L7で設計行列と残差化対象が異なる。`E_adj` の再計算方法がレンズ別に定義されていない。
- **仮に進めるならどうするか**: 各レンズの最小観測単位に交絡差分を作り、同じ効果統計を residualized Endpoint で再計算する。L2a は pair の交絡差、L2b は系列内で交絡回帰後の残差、L1b/L5 は化合物残差、L7 は系列内 residualized Endpoint、L4 は到達元と生成物の予測交絡差を使う。

**ただし投資を抑えてよい。** 較正で交絡（MW / cLogP / TPSA）が説明する Endpoint 分散は **7% のみ**であり、`non_triviality` は多くの Finding で 1 に近くなる。**強い識別軸にはならないため、レンズ別の実装差は最終順位にほとんど影響しない。** 簡潔な実装で十分である。

## Q-014 T01〜T10 の実行可能な契約

- **区分**: blocking
- **出所**: 実装計画書 段階9 / design/deep_dive_protocol.md 3章
- **何が不明か**: 各テンプレートは問いの名称まではあるが、必須パラメータ、最小 n、実行する統計量、補正の族、出力列、SURVIVED/WEAKENED 判定へ渡す値が未定である。固定テンプレート関数のシグネチャを確定できない。
- **仮に進めるならどうするか**: 各テンプレートを `execute(parent_finding, parameter_object, artifact_registry) -> DeepDiveTestResult` に統一し、まず設計文書から機械的に決まる T05/T06/T07/T08/T09/T10 を実装する。T01〜T04 はレンズ別 parameter schema と最小 n が承認されるまで `not_available` とする。
- **その案で進めた場合の影響**: 全10個を完成条件とするなら Phase 5 を完了できない。後から parameter schema を変えると LLM prompt と契約テストの更新が必要だが上流は再利用できる。

**回答**: **一部却下。T01 を `not_available` にしないこと。**

T01（部分集合分割）は深堀で最も価値の高いテンプレートであり、これを外すと Phase 5 が骨抜きになる。**機械算出の分割軸だけで実装できる。**


プロジェクト固有 SMARTS は**後から足せる追加の軸**にすぎず、T01 の前提条件ではない。

## Q-016 Local LLM の呼出方法と失敗時再試行

- **区分**: non-blocking
- **出所**: 実装計画書 段階9〜10 / design/llm_operating_contract.md 8章
- **何が不明か**: オフライン27Bという前提だけで、実行コマンド/API、model ID、timeout、JSON schema違反時の再試行回数、context上限が未定である。
- **仮に進めるならどうするか**: `llm.command` に JSONL stdin/stdout を扱うローカルコマンドを設定する provider interface を作る。既定は未設定で fail-fast、schema違反は同一入力で2回まで再試行し、その後は当該 Finding を `INCONCLUSIVE` ではなく Phase failure とする。
- **その案で進めた場合の影響**: provider adapter の差し替えで対応できる。決定論層と Artifact schema は変更不要。

**回答**: **provider interface は承認。ただし失敗時の方針を1点変更する。**

**個別の LLM 失敗で Run 全体を止めないこと。** schema 違反は再試行後、当該 Finding を「narrative なし」で報告して続行し、**失敗率が閾値を超えた場合にのみ Phase を失敗させる**。

引用不整合はこれと区別する。引用不整合は**正しさの問題**であり、1件でも Phase 6 を失敗させる（実装計画書 10.2 のとおり）。
