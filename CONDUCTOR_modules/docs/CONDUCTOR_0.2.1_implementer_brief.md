## 2. 実装に着手する前に作る2つの文書

**コードを書き始める前に、次の2つを作ってください。**

### 2.1 不明点の整理

パス: `CONDUCTOR_modules/docs/CONDUCTOR_0.2.1_implementation_questions.md`

実装計画書を読んで判断がつかなかった点を、次の形式で列挙してください。

```markdown
## Q-001 <一行の見出し>

- **区分**: blocking / non-blocking
- **出所**: 実装計画書 8.1 節 / design/finding_model.md 4章 など
- **何が不明か**: （具体的に。「よくわからない」ではなく「X と Y のどちらか判断できない」）
- **仮に進めるならどうするか**: （あなたの案。根拠も）
- **その案で進めた場合の影響**: （後戻りの大きさ）
```

区分の基準は次のとおりです。

- `blocking`: これが決まらないとコードが書けない、または書いても捨てることになる
- `non-blocking`: 仮の案で進められ、後から差し替えられる

**「実装計画書 9章（実装前に確認を要する事項）」に既に挙がっている5件は、重複して書かなくて構いません。**
それ以外で見つかったものを書いてください。

**関数シグネチャ、データ構造、ファイル形式、エラー処理までは書いていません。**

最低限、次を含めてください。

## 3. 実装の進め方

### 3.1 段階0: 既存 0.1.x 資産の仕分け

**最初にこれをやってください。** 実装計画書 3.1 節に処遇の表があります。

リポジトリには 0.1.x の実装（スキル42個、catalog、schemas、tools、tests）が残っています。
表に従って `Archive/` へ退避し、`.gitignore` へ追加してください。**削除はしないでください。**

### 3.2 実装順序

実装計画書 5章の順序を守ってください。特に次を守ること。

> **段階3（統計基盤・並べ替え）を、レンズより先に作る。**

全レンズがこれに依存し、ここを誤ると全結果が無効になります。
較正では並べ替えの実装を誤ると enrichment を 50 倍過大評価することが実測されています。

### 3.3 段階6 で必ず一度止まる

L2b（主力レンズ）を実装し終えたら、**先へ進まずに報告してください。**

実装計画書 8章の受け入れ基準に従い、較正データで次を確認します。

```text
L2b の enrichment が 2.07 / 2.31 / 2.54 を ±30% で再現するか
```

再現できなければ、残りのレンズを実装しても無駄になります。原因を特定してから進みます。

## 4. 守ってほしいこと

### 4.1 独断で決めない

実装計画書 9章に「実装前に確認を要する事項」が5件あります。**それ以外は本書と実装計画書で
決定済みです。** 迷いが生じたら、次の順で確認してください。

```text
1. 実装計画書を読み直す
2. design/calibration_results.md で数値の根拠を確認する
3. それでも決まらなければ 2.1 の質問文書へ書き、設計担当へ報告する
```

**勝手に決めて進めないでください。** 設計は実データの計測に基づいており、
一見些細な変更が受け入れ基準を壊すことがあります。

### 4.2 実装してはいけないもの

実装計画書 1章に8項目あります。特に次の3つは**実測で却下されたもの**であり、
「一般的にはあった方がよさそう」という理由で復活させないでください。

| 項目 | 却下理由 |
|---|---|
| L1a（空間水準の説明力） | 全空間で不在 |
| L3（局所期待からの逸脱） | enrichment 1.02〜1.08。並べ替えと区別がつかない |
| L6（活性濃縮クラスタ） | enrichment 0.98〜1.01。検出しているのは骨格そのもの |

これらは**診断指標として計算し報告してよい**が、Finding を生成してはいけません。

### 4.3 パラメータをハードコードしない

実装計画書 2章の確定パラメータは、すべて設定ファイルの既定値として置いてください。
**別プロジェクトへ適用する際に再測定が必要な値が含まれます**（特に測定 σ = 0.10）。

### 4.4 既知の落とし穴

実装計画書 4.2 節に、診断モジュールの実装で実際に踏んだバグが参照実装つきで書いてあります。
**環系置換が 0 ペアになる原因**です。必ず読んでください。

## 5. 前提となる実行環境

- 各スキルは Pixi (`env/pixi.toml`) で自己完結させる

- 相当量の計算リソース（多コア CPU を長時間）が利用可能である前提で並列化する
