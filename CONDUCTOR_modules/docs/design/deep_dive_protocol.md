# 深堀プロトコル

Status: **設計協議中。未承認・未実装。テンプレート集合は Chemist との協働で確定する。**

親文書: [`../CONDUCTOR_0.2.1_specification_overview.md`](../CONDUCTOR_0.2.1_specification_overview.md)

## 1. なぜ深堀が必要か

0.1.x は1パスだった。解析し、並べ、終わり。深堀は人間の仕事として残された。実戦投入の結果、**深堀こそが最も重要な工程であり、そこが人間へ丸投げされていることが負担の主因**であると判明した。

0.2.1 では深堀を**再帰的な機械処理**にする。

深さは知性からではなく**回数**から出す。1件の Finding を20〜50回の小さな検定へ展開する。どれも人間にできる作業だが、人間がやりたがらない作業である。これは Local LLM の適性そのものである。

> 1回の深い洞察ではなく、1000回の浅い作業の集積で深さに到達する。

## 2. 中核の設計判断: 子問いを自由記述させない

**LLM に自由文で子問いを書かせると、それを実行する側が「何の検定をすればよいか」を解釈しなければならず、そこで型が崩れる。**

したがって子問いは**固定テンプレート集合からの選択とパラメータ埋め**に限定する。

```text
LLM の仕事   T01〜T10 のどれを、どのパラメータで呼ぶかを「選ぶ」
決定論層     選ばれたテンプレートを実行する（実装済みの関数）
```

これにより:

- 自由記述の危うさを避けつつ、分岐の柔軟性は保てる
- 「どの検定を走らせるか」が常に一意に定まり、監査できる
- 27B クラスのモデルでも安定して動く（選択タスクは生成タスクより易しい）

## 3. テンプレート集合

### 3.1 汎用テンプレート

| ID | 名称 | 問い | 適用レンズ |
|---|---|---|---|
| `T01` | 部分集合分割 | 条件 C の中に、効果が現れない部分集合はあるか | 全 |
| `T02` | 単調性確認 | 効果は指定軸に沿って単調か | L1, L2, L5 |
| `T03` | 類似文脈への汎化 | 似た性質を持つ別の文脈でも同じ効果が出るか | L1, L2, L5, L6 |
| `T04` | 類似対象への汎化 | 構造的に近い変換／特徴量も同じ挙動か | L2, L5 |
| `T05` | 頑健性再検定 | bootstrap 再抽出で方向と有意性が保たれるか | 全 |
| `T06` | 未適用対象の列挙 | 条件 C 内で、この変換が未適用の化合物はどれか | L2, L4 |
| `T07` | 交絡の分解 | 効果のうち各交絡軸が説明する割合はどれだけか | 全 |
| `T08` | 影響度分析 | 単一化合物／単一ペアを除くと結論が変わるか | 全 |
| `T09` | 標本サイズ依存 | 効果は小標本由来の見かけか（同サイズ無作為抽出との比較） | 全 |
| `T10` | 反例探索 | 主張に反する観測を明示的に探す | 全 |

`T10` は意図的に含めている。**反例を探しに行かせることが、弱いモデルの確証バイアスに対する構造的な対抗手段**になる。

### 3.2 `T01` の分割軸ライブラリ

`T01`（部分集合分割）は最も有用なテンプレートであり、**化学的に意味のある分割軸**を要する。

| 分割軸 | 定義方法 | 状態 |
|---|---|---|
| 骨格クラス | Murcko / MCS | 機械的に算出 |
| 置換基サイズ | heavy atom 数 | 機械的に算出 |
| 極性・水素結合能 | TPSA, HBD/HBA | 機械的に算出 |
| 環の有無 | 環構造の有無 | 機械的に算出 |
| 立体化学 | stereocenter の有無・配置 | 機械的に算出 |
| 置換基の電子効果 | Hammett σ ＋ 部分電荷（下記 3.3） | 機械的に算出 |
| 置換位置 | 骨格上の attachment 位置（下記 3.4） | 機械的に算出 |
| **プロジェクト固有の構造モチーフ** | 人間が与える SMARTS | **要提供** |

### 3.3 置換基の電子効果

**用語**: 芳香環などに付いた置換基には、環から電子を引き寄せるもの（電子求引基 / EWG: F, CF₃, NO₂, CN, C=O など）と、環へ電子を押し込むもの（電子供与基 / EDG: OMe, NH₂, alkyl など）がある。同じ位置への置換でも、この向きが逆だと活性への効き方が逆転することが多く、**SAR で置換基を分類する最も古典的な軸**である。

機械的に算出できるため、Chemist の定義提供は不要とする。三段構えで求める。

```text
1. 既知置換基は Hammett 定数（σp / σm）のルックアップ表を引く
     → 最も解釈しやすく、化学者が慣れた尺度
2. 表に無い置換基は Gasteiger 部分電荷から推定する
     → attachment 原子および fragment 全体の電荷を使う。RDKit 標準機能で全化合物に適用可能
3. xTB (D019) が利用可能な場合、量子化学由来の原子電荷で検証する
```

区分は3値とする。

```text
EWG      σ > +閾値
neutral  −閾値 ≤ σ ≤ +閾値
EDG      σ < −閾値
```

Finding へ表示する際は、推定に使った経路（Hammett 表 / 部分電荷 / xTB）を併記する。ルックアップ表由来か推定値かで信頼度が違うためである。

閾値は実データで較正する。

### 3.4 置換位置

MMP の attachment point が骨格上のどの位置に対応するかで分割する。汎用的な ortho / meta / para は単環芳香族に限られるため、一般には**骨格ごとに attachment 原子の index を正規化して位置ラベルとする**。

骨格が共通の pair 集合内でのみ意味を持つ分割軸であり、骨格を跨いだ位置の比較は行わない。

### 3.5 プロジェクト固有 SMARTS の扱い 【要提供】

人間が SMARTS パターンを複数与える。これが唯一、外部からの提供を要する項目である。

**重要な制約**: 与えられるパターンは互いに排他とは限らない。**パターン A がパターン B の部分集合であるケースがある。** したがって `T01` は「排他的な分割」を前提にしてはならない。

設計上の対応:

```text
1. 各パターンは「該当する / しない」の二値フラグとして独立に扱う
   （相互排他な分割としては扱わない）
2. 分割は常に「パターン P に該当する群 vs 該当しない群」の二分とする
3. パターン間の包含関係を事前に検出し、記録する
     A ⊂ B が成り立つ場合、A で有意、B で非有意 なら
     「効果は B 全体ではなく A に限定される」という精緻化として解釈する
4. 包含関係にあるパターン群では、多重比較補正を階層を考慮して行う
```

3 の解釈は実務上有用である。広いパターン B では効果が薄まり、狭いパターン A で濃く出る場合、**効果の所在が A にあることが特定できる**。これは `WEAKENED`（主張の精緻化）の典型例である。

提供形式:

```yaml
project_patterns:
  - pattern_id: PP_001
    name: "<人間が読む名前>"
    smarts: "<SMARTS>"
  - pattern_id: PP_002
    name: "<人間が読む名前>"
    smarts: "<SMARTS>"
```

包含関係は与えられた SMARTS から機械的に検出するため、人間が申告する必要はない。

## 4. ループ仕様

```text
入力: 段階B で ranked となった Finding（上位 K 件）

各 Finding について:

  1. ノードをキューへ積む（depth = 0、親 = なし）

  2. LLM がノードを見て、テンプレート集合から子問いを最大3つ選ぶ
     - 選ばなくてもよい（これ以上掘る価値が無いと判断した場合）
     - 各子問いはテンプレート ID とパラメータの組で表現される
     - 親ノードで既に実行済みの (テンプレート, パラメータ) は選べない

  3. 決定論層が各子問いを実行し、結果を返す

  4. LLM が結果を見て、各子ノードの状態を判定する
       SURVIVED      主張と整合
       WEAKENED      主張は部分的にのみ成立（境界条件を発見）
       REFUTED       主張と直接矛盾
       INCONCLUSIVE  サンプル不足等で判定不能

  5. 継続条件を全て満たす場合、SURVIVED / WEAKENED のノードを次段へ送る（2 へ戻る）
       - depth < 3
       - 検定実行回数の予算が残っている
       - 直前2つの子ノードが両方 INCONCLUSIVE ではない

  6. REFUTED が1件でも出た場合、その枝を即座に停止し、
     親 Finding の状態を WEAKENED または REFUTED へ引き下げる

  7. 予算到達または全枝終了で打ち切る

  8. LLM が木全体を引用付きの短い narrative へ要約する
```

### 停止条件

| 条件 | 値（初期案） |
|---|---|
| 最大深度 | 3 |
| ノードあたり最大分岐 | 3 |
| Finding あたり検定実行回数 | 15 |
| 連続 INCONCLUSIVE で枝を打ち切る | 2 |

`REFUTED` による即時停止は予算と独立に働く。矛盾が出た時点でその枝を掘り続ける意味は無い。

## 5. 状態の扱い

### `WEAKENED` は失敗ではない

「この変換が効くのは文脈 C のうち骨格 A を持つサブセットに限る」という結果は、主張の**精緻化**である。元の主張より対象は狭まるが、**より正確で、より行動しやすい**。

報告では、精緻化された主張を主とし、元の広い主張を経緯として添える。

### `REFUTED` の扱い

報告からは外すが、削除しない。何が棄却されたかは診断情報である。特に、同じテンプレートで多数の Finding が `REFUTED` になる場合、それは段階A のスクリーン設計に問題があることを示す。

### `INCONCLUSIVE` の扱い

サンプル不足は情報である。「この方向は現在のデータでは判定できない」は、追加データ取得の判断材料になる。narrative に明記する。

## 6. 出力形式

**木構造をそのまま見せない。** 引用付きの短い narrative へ要約する。

木の全体は別 Artifact（JSON）として保持し、必要なら辿れるようにする。

## 7. 実行例

以下は動作を示すための例であり、数値は架空である。

```text
Finding F000042: 変換 [4-F-phenyl → 4-CF3-phenyl] は文脈 C007-12 でのみ活性を上げる
                 中央値 +0.62 (n=7, 方向一致 7/7), 交互作用 BH q=0.04
                 depth 0

  ├─ T05 頑健性再検定 (bootstrap B=500)
  │    → 方向一致率の 95% 区間 0.71–1.00。方向は安定
  │    depth 1, SURVIVED
  │
  ├─ T01 部分集合分割 (分割軸: 骨格クラス)
  │    → 骨格 A: +0.81 (n=4)
  │      骨格 B: +0.31 (n=3, 非有意)
  │    depth 1, WEAKENED
  │    → 主張の精緻化: 「骨格 A のサブセットでのみ強く効く」
  │      │
  │      └─ T06 未適用対象の列挙 (骨格 A ∩ C007-12、当該変換が未適用)
  │           → CPD-0231 (pIC50 8.6), CPD-0447 (8.4)
  │           depth 2, SURVIVED
  │
  └─ T03 類似文脈への汎化 (C007-09, C007-15)
       → C007-09: n=3, 方向不一致, 非有意
         C007-15: n=2, 判定不能
       depth 1, INCONCLUSIVE
       → この枝は打ち切り（連続 INCONCLUSIVE ではないが、サンプル不足で深掘り不能）

検定実行回数: 4 / 15
最終状態: WEAKENED（精緻化）
```

生成される narrative:

```text
変換 [4-F-phenyl → 4-CF3-phenyl] は文脈 C007-12 で活性を上げる
（中央値 +0.62 log, n=7, BH q=0.04）。Bootstrap 再抽出でも方向は安定している
（方向一致率 95% 区間 0.71–1.00, T05）。ただし効果は骨格 A のサブセットに集中しており
（+0.81, n=4）、骨格 B では弱い（+0.31, n=3, 非有意, T01）。
骨格 A かつ C007-12 に属し、この変換が未適用の化合物は CPD-0231 (8.6) と
CPD-0447 (8.4) であり、次の候補として提案できる（T06）。
他文脈への汎化は現時点でサンプル不足のため判定不能（C007-09: n=3, C007-15: n=2, T03）。
```

narrative 中の全ての数値は `citations` の指す行に存在しなければならず、Phase 6 で機械検証される（[`finding_model.md`](finding_model.md) 第7章）。

## 8. LLM が担う判断とその根拠

深堀ループの中で LLM が行うのは次の3つだけである。

| 判断 | 難易度 | 27B での妥当性 |
|---|---|---|
| どのテンプレートをどのパラメータで呼ぶか | 選択タスク | 妥当。選択肢が10個に限定される |
| 検定結果が4状態のどれか | 分類タスク | 妥当。閾値の大半は決定論層が計算済み |
| 木全体の narrative 要約 | 生成タスク（引用強制） | 妥当。引用可能範囲でしか書けない |

**発見も順位付けも LLM は行わない。** それらは段階A/B で決定論的に完了している。
