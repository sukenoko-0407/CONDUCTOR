# 候補生成とスコアリング

Status: **設計協議中。未承認・未実装。**

親文書: [`../CONDUCTOR_0.2.1_specification_overview.md`](../CONDUCTOR_0.2.1_specification_overview.md)

## 1. 問題設定: 何を「起点」にするか

0.1.x では FF ≥ 0.50 という単一ゲートが、**3つの異なる役割を同時に担っていた**。

1. 計算量の削減
2. 統計的に意味のある候補の絞り込み
3. 人間の関心が高い活性域への誘導

3つを1つのフィルタで行ったため、選抜後に同じ Endpoint で記述する構造となり、循環と範囲制限が生じた。

0.2.1 では役割を分解し、別々の段階へ配置する。

```text
段階A   レンズ別の安価な統計スクリーン        ← 役割 1, 2
段階B   共通スコアリング（足切り＋順位付け）   ← 役割 2
段階C   frontier 近接度による重み             ← 役割 3
```

**役割3を統計計算から完全に切り離すことが要点である。** 統計は全域データで計算するため範囲制限を受けず、人間の関心は事後の重みとしてのみ反映される。

これにより「7→8 の変換それ自体に関心は無いが、その証拠を pIC50 9 の化合物へ適用できるなら価値がある」が表現できる。**証拠の活性域と適用先の活性域を分離する。**

## 2. 条件の語彙

### 2.1 4種類の条件

| 種類 | 生成元 | 概数（1000化合物想定） |
|---|---|---|
| クラスタ所属 | 全 Clustering × 全 Description | 数百〜数千 |
| 特徴量の範囲分割 | Tier 1/2 特徴量の分位点分割 | 数百 |
| 骨格クラス | Murcko / MCS / BRICS / RECAP | 数十 |
| 活性域 | frontier / 中域 / 低域 | 数個 |

活性域を条件として使う場合、それを使ったレンズの結果は範囲制限の影響を受けるため、**活性域条件は L6 および診断目的に限定**し、L1/L2/L5 の主たる条件としては使わない。

### 2.2 文脈カタログの正規化

生成される条件は多すぎ、かつ重複する。報告前に正規化する。

```text
1. 最小サイズ  Endpoint 有効 N < 下限 の条件を除く
2. 重複排除    Jaccard 係数が閾値以上の条件ペアは一方を代表として残す
               （異なる Clustering が実質同じ群を作ることは頻繁に起きる）
3. 補集合の扱い  条件 C とその補集合を別条件として二重計上しない
4. 翻訳        各条件を Tier 1/2 の語へ翻訳し、翻訳可否を記録する
```

重複排除は計算量の抑制と、**同じ知見が複数レンズから重複して報告されることの防止**の両方に効く。

### 2.3 条件付け深度

**深度は 1 とする。単一条件のみを文脈として使う。**

```text
深度1   単一条件           C₁                              ← 0.2.1 はここまで
深度2   異なる軸の組合せ    C₁ ∧ C₂  （例: クラスタ ∧ logP 分位）  ← 0.2.2 の検討事項
```

深度2を 0.2.1 で実装しない理由は次の2点である。

- 較正データで深度1の文脈が **270** あり、Jaccard 0.9 の重複排除後でも十分な数が残る
- 深度2は文脈数が組合せで増えて多重比較の族が膨らむ一方、**その細かさに見返りがあるかが未測定**である

深度2は 0.2.2 で、診断により有効性を確認してから導入する。
導入する場合も、**同じ軸から生じた条件同士は組み合わせない**（同一 Clustering の2クラスタの積は
通常空になる）。異なる軸に限定して組合せ数を抑える方針は維持する。

深度3以上は扱わない。サンプルサイズが急速に枯渇し、多重比較の負担に見合わない。

## 3. 段階A: レンズ別スクリーン

各レンズが自前の安価な統計スクリーンを持つ。詳細は [`discovery_lenses.md`](discovery_lenses.md) を参照。

共通の要件は次の通り。

- 条件に属する Endpoint 有効化合物数が下限以上
- BH 補正後の q 値が閾値以下
- 条件が翻訳可能（Tier 3 由来の場合）
- 反証条件が機械的に構成できる

**この段階では絞りすぎない。** 出力は候補プール（数百〜数千件）であり、絞り込みは段階Bが担う。0.1.x の失敗は、この段階で強く絞ったことにある。

### 3.1 計算量の集中点

| レンズ | 組合せ数の目安 | コストの所在 |
|---|---|---|
| L1 | 文脈 × Tier1/2 空間 | 帰無分布の反復（B 回の λ 計算）。**最も重い** |
| L2 | 変換 × 文脈 × 3クラス | 大半は n ≥ 3 を満たさず即座に落ちるため実質は軽い。環系置換は fragmentation のコストが乗る |
| L3 | 化合物 × 空間 | 近傍計算は空間ごとに一度で済む |
| L4 | 領域 × 到達経路 | L2 の変換 DB への照合 |
| L5 | 特徴量 × 文脈ペア | **ペアの列挙が爆発しうる**（後述） |
| L6 | 文脈 | 軽い |
| L7 | 骨格ペア × 共通 R 基 | 共通 R 基下限を満たすペアのみに限定されるため実質は軽い |

**L5 の文脈ペア列挙の抑制**: 全文脈の総当たりペアは組合せ爆発する。**同じ分割軸から生じたペアに限定する**（同一 Clustering 内の2クラスタ、同一特徴量の2分位など）。これは計算量の抑制であると同時に、**比較の意味が明確になる**という利点がある。異なる軸から来た2群を比較しても「何が違うから符号が逆なのか」を語れない。

**L1 の帰無分布の抑制**: B 回の反復が最も重い。段階的に行う。まず B を小さく（例 100）して明らかに有意でない候補を落とし、残った候補にのみ大きな B を適用する。

## 4. 段階B: 共通スコアリング

### 4.1 二段構え

異種の Finding（p 値・残差 z・密度ギャップ・オッズ比）は単位が違うため単純比較できない。共通軸へ落とし込む。

```text
足切り:  statistical_strength ≥ θ₁  AND  robustness ≥ θ₂
順位:    composite = non_triviality × actionability × frontier_relevance
```

**加重和ではなく、足切り＋積を使う。** 加重和では「統計的に弱いのに派手に見える」候補が上位へ来る事故が起きる。先に統計で足切りし、通った候補群の中でのみ化学的な面白さと行動可能性で順位を付ける。

### 4.2 5つの軸

| 軸 | 算出 | 範囲 |
|---|---|---|
| `statistical_strength` | q 値を**レンズ内パーセンタイル**へ変換（型を跨いで比較可能にする） | [0, 1] |
| `robustness` | bootstrap 再抽出 B 回で主張の方向と有意性が保たれた割合 | [0, 1] |
| `non_triviality` | 1 −（交絡調整で説明された効果の割合）。調整後効果 / 元効果 | [0, 1] |
| `actionability` | 次の一手がどこまで一意に定まるか | [0.2, 1.0] |
| `frontier_relevance` | 示唆する一手が到達しうる活性水準と観測上位との近さ | [0, 1] |

生の p 値ではなく**レンズ内パーセンタイル**を使うのは、検定手続きが異なるレンズ間で p 値を直接比較することに意味がないためである。

### 4.3 `actionability` の刻み

| 値 | 条件 | 該当例 |
|---|---|---|
| 1.0 | 具体的な化合物 ID と適用する変換が両方一意に定まる | L2, L4 |
| 0.6 | 最適化の方向は定まるが、対象化合物が一意でない | L1, L5 |
| 0.2 | 記述のみ。次の一手を示さない | L6, 一部の L3 |

下限を 0 ではなく 0.2 とするのは、積によって L6 の Finding が完全に消えることを避けるためである。L6 は順位で下がるべきだが、消えるべきではない。

### 4.4 `non_triviality` の算出

交絡として最低限 MW / cLogP / TPSA / 骨格クラス を調整する。

```text
元の効果      E_raw
調整後の効果  E_adj  （交絡を回帰で落とした後に残る効果）
non_triviality = E_adj / E_raw   （0 未満は 0 へ丸める）
```

脂溶性を上げることで説明できてしまう活性向上は `trivial` とラベルされ、既定表示から外れる。**脂溶性を上げずに活性が上がっている**変換は高い値を取り、上位へ来る。

## 5. 段階C: frontier 近接度

### 5.1 定義

```text
frontier_relevance(finding) =
  この Finding が示唆する次の一手を実行した結果、到達しうる活性水準が、
  観測済み上位活性にどれだけ近いか
```

### 5.2 事前フィルタにしない理由

0.1.x はこれを FF ≥ 0.50 として**入力段階**に置いた。結果として範囲制限が生じ、通過する候補が自明な軸（分子サイズ・脂溶性）へ偏った。小規模な検証 fixture では通過件数そのものが 0 になったが、実戦規模のデータでは件数が 0 になるのではなく**通るものの質が落ちる**形で現れる。

0.2.1 では**事後の重み**とする。統計は全域データで計算されるため歪まない。優先順位付けだけが人間の関心に沿う。

### 5.3 証拠と適用先の分離

この設計により次が表現できる。

```text
証拠   pIC50 7 → 8 の変換ペアで観測された（低活性域）
適用先 pIC50 8.9 の化合物にこの変換は未適用（frontier 上）
→ frontier_relevance は高い
```

「7→8 の変換に意味はあるか」という問いへの答えは、**それ単体では低いが、frontier の化合物へ転用できるなら高い**である。0.1.x は証拠の活性域で足切りしていたため、この転用経路ごと捨てていた。

## 6. 出力

段階B を終えた時点で、全候補が以下の状態を持つ。

```text
screened_out   足切りで落ちた。理由と各軸のスコアを保持
ranked         上位 K 件。Phase 5（深堀）へ進む
```

**削除はしない。** 落ちた候補も CSV / JSON から辿れる。

段階B までは完全に決定論的であり、LLM は関与しない。発見と順位付けは統計と閾値の仕事である。
