# LLM 運用契約

Status: **設計協議中。未承認・未実装。**

親文書: [`../CONDUCTOR_0.2.1_specification_overview.md`](../CONDUCTOR_0.2.1_specification_overview.md)

## 1. 前提

CONDUCTOR は **Local LLM（Qwen3 27B クラス）** を前提とする。

- オフライン。Web 検索・外部 API を使えない
- 商用フロンティアモデル（Opus / GPT 等）ほどの知性は無い
- 一方で、**大量の小さなタスクを黙々とこなす能力は十分にある**

### 勝ち筋

> 優れた知性に依存するのではなく、人間でもできる内容の処理を大量にやる。

これが設計の基本方針である。1回の深い洞察を期待せず、**1000回の浅い作業の集積**で深さに到達する。

## 2. 分業線

| 層 | 担当 | 理由 |
|---|---|---|
| 発見（何が注目に値するか） | **決定論層** | 統計と閾値の仕事であり、そもそも LLM の仕事ではない |
| 順位付け | **決定論層** | スコアリングは算術である |
| 説明・接続 | **LLM** | 言語の仕事 |
| 深堀の分岐選択 | **LLM** | 選択タスク。選択肢が限定される |
| 状態判定 | **LLM**（決定論化も可） | 分類タスク |

### 0.1.x の分業線が間違っていた

0.1.x では I001（Interpretation）に「定型 Summary を読んで意味を抽出せよ」と頼んでいた。これは**発見**を任せている。168節のレポートから何が重要かを見抜く作業であり、27B には重い。

そして実際には、そもそも**入力が薄かった**。

> **I001 の出力が薄いのは、I001 の入力が薄いからでもある。**
> 中身のない168節を渡されて深い考察を書ける言語モデルは存在しない。

0.2.1 では決定論層が発見と順位付けを終えた後、LLM には次を頼む。

```text
「この5件の Finding を化学的に説明し、つなぎ、次の一手を書け」
```

これは articulation のタスクであり、27B の射程内である。**上流を直せばモデルを替えずに出力が濃くなる**可能性が高い。

## 3. タスク分解の原則

LLM へ渡すタスクは次を満たすこと。

1. **単一の判断**を求める（複数の判断を1回に混ぜない）
2. **入力が小さい**（1画面に収まる程度の構造化データ）
3. **出力スキーマが固定**（自由記述の余地を最小化）
4. **「該当なし」を返せる**（空の出力が正当な回答であること）

4番目は 0.1.x への直接の反省である。「0件でも参考・基準未達を1件表示する」という規則は、**モデルに水増しを強制する**。0.2.1 では空を返すことを正当な選択肢とする。

### 具体的なタスク一覧

| タスク | 入力 | 出力 | 想定呼出回数 |
|---|---|---|---|
| 文脈の言語化 | 判別モデルの寄与記述子 | Tier 1/2 の語による記述 | 数十 |
| 深堀の分岐選択 | ノードの状態と既実行テンプレート | テンプレート ID × パラメータ（最大3、0 可） | K × 深度 |
| 検定結果の状態判定 | 子問いの結果 | 4状態のいずれか | K × ノード数 |
| narrative 要約 | 深堀木と引用可能な行 | 引用付きの短い文章 | K |
| Finding 間の関連付け | 上位 Finding の主張一覧 | 関連の指摘（0 件可） | 数回 |

### 計算量の目安

上位 K = 20、Finding あたり深堀ノード ~15 とすると:

```text
分岐選択    20 × 15        =  300 回
状態判定    20 × 15        =  300 回
narrative   20             =   20 回
文脈言語化  ~50            =   50 回
関連付け    ~5             =    5 回
                          合計 約 675 回
```

**約700回の小さな呼出**で1 Run が完結する。これは Local LLM の運用として現実的であり、「1000回の浅い作業」という方針とも整合する。

## 4. 引用強制

### 4.1 規則

> narrative 内の全ての主張は、`citations` の行を指さねばならない。

LLM には**引用可能な行の集合**を明示的に渡し、その外の主張を書かせない。

### 4.2 二つの効果

**監査可能性**: 決定論からではなく、引用の検証可能性から得る。LLM に判断させつつ、根拠のない主張を機械的に落とせる。Phase 6 で引用整合性を検証し、不整合が1件でもあれば失敗させる。

**出力品質**: 引用強制は**弱いモデルの脱線を防ぐ拘束具**として実用的に効く。「引用できる範囲でしか書けない」という制約が、27B クラスの出力品質を実質的に押し上げる。これは監査のための副作用ではなく、狙った効果である。

### 4.3 検証項目

1. narrative 内の全数値が `citations` の指す行に存在するか
2. 引用された compound_id / pair_id が Run 内に実在するか
3. 引用された table_ref が実在し、行番号が有効か
4. `test` の p 値・q 値が対応する検定結果と一致するか

**報告を自動修正しない。** 不整合は失敗として報告する。

## 5. 型による拘束

[`finding_model.md`](finding_model.md) の型と、[`deep_dive_protocol.md`](deep_dive_protocol.md) のテンプレート集合が、LLM の出力空間を構造的に制限する。

| 拘束 | 効果 |
|---|---|
| 反証条件を必須にする | 反証できない主張を検定前に排除。確証バイアスへの対抗 |
| 子問いをテンプレート選択に限定 | 「何の検定をすればよいか」の解釈の余地を消す |
| 出力スキーマ固定 | パースの失敗と自由記述の暴走を防ぐ |
| 引用可能行を明示 | 幻覚の余地を構造的に削る |

**型が LLM の出力制御と検定の自動化を同時に担う**というのが設計の要点である。人間の言葉と機械の手続きが一つのフィールドで繋がる。

## 6. LLM に判断させないこと

次は LLM に任せない。

- どの Finding が統計的に有意か（決定論層が計算する）
- Finding の順位（スコアリングが決める）
- 閾値の設定・変更
- 検定手法の選択（テンプレートが固定する）
- 数値の算出（全て決定論層が出したものを引用するだけ）
- 画像・図の内容判定（LLM Vision / screenshot 解釈は使用しない）

最後の項目は 0.1.x の方針を踏襲する。化学構造の正しさは元 SMILES、描画成功、原子 index、生成物 validation で検証する。

## 7. 反復パターン

深堀は次の4段を1サイクルとする。

```text
propose   → LLM がテンプレートとパラメータを選ぶ
test      → 決定論層が実行する
judge     → LLM が4状態のいずれかへ分類する
summarize → LLM が引用付きで要約する（サイクル終了時に1回）
```

各段が独立した小タスクであり、失敗しても局所的に再試行できる。1回の大きな統合を避け、**小さく区切ったタスクの連鎖**にすることが 27B を活かす鍵である。
