# Endpoint モデルと MPO 対応

Status: **設計協議中。未承認・未実装。**

親文書: [`../CONDUCTOR_0.2.1_specification_overview.md`](../CONDUCTOR_0.2.1_specification_overview.md)

## 1. 方針

> **単一 Endpoint で確実に仕事ができることを最優先とする。ただし多目的最適化（MPO）へ拡張できる構造で作る。**

0.2.1 が実際に届けるのは単一 Endpoint の解析である。しかし Endpoint を「1本の列」として設計に埋め込むと、後から MPO を載せる際に全面改修になる。したがって**最初から複数 Endpoint を表現できるデータモデル**を採り、解析側は 0.2.1 では単一 Endpoint モードだけを実装する。

| | 0.2.1 で実装 | 拡張点として確保 |
|---|---|---|
| Endpoint レジストリ | ✓ 複数登録可能 | — |
| Finding の Endpoint 参照 | ✓ 単一を参照 | 複数参照 |
| 単一 Endpoint レンズ（L1〜L7） | ✓ | — |
| 横断レンズ（M1〜M3） | 契約のみ定義 | 実装 |
| Pareto / トレードオフ解析 | — | 実装 |

### 1.1 Run の単位

> **1 Run = 1 Endpoint。**

Endpoint ごとに Run を分ける。構造に依存する成果物（Description、文脈カタログ、MMP fragmentation、空間の距離構造）は Run を跨いで再利用し、Endpoint に依存する量だけ再計算する。

MPO 的な視点へは、複数 Run の Finding を突き合わせる形で後から到達する。**まず単一 Endpoint で確実に知見を抽出できることを優先する。**

## 2. Endpoint レジストリ

Endpoint は Run 単位で複数登録できる。

```yaml
endpoints:
  - endpoint_id: EP_EC50
    role: primary
    kind: measured
    source_column: ec50_nm
    transform: neg_log10        # pEC50 へ変換
    direction: higher_is_better
    unit: log_molar
    coverage: 900               # Endpoint 有効化合物数

  - endpoint_id: EP_FOLD_WT_MUT
    role: secondary
    kind: derived               # 他 Endpoint から算出される
    derivation:
      type: ratio
      numerator: EP_EC50_MUT
      denominator: EP_EC50_WT
    direction: higher_is_better
    unit: fold
    coverage: 500
```

### 2.1 `kind` の区別

| kind | 意味 | 注意 |
|---|---|---|
| `measured` | 直接測定された値 | — |
| `derived` | 他 Endpoint から算出される（比・差） | **元 Endpoint と統計的に独立ではない** |

### 2.1.1 評価系の変更は別 Endpoint として扱う 【重要】

大きな実験条件の変更があり、新旧の測定値が**別カラム**に分かれている場合がある。このとき**両カラムが埋まっている化合物はほとんど存在しない**ことが多い。

```text
旧評価系カラム: 主に初期の化合物
新評価系カラム: 主に後期の化合物
両方が埋まっている化合物: ほぼ無い
```

> **規則: 重なりの無い評価系カラムを1つの Endpoint へ統合してはならない。**

重なりが無いということは、**系統的なオフセットを推定する手段が無い**ことを意味する。橋渡しできる化合物がないまま2カラムを連結すると、新旧の差が Endpoint 値の差として混入する。

さらに悪いことに、測定時期は構造と相関する。初期の hit 系列と後期の最適化系列は構造が違う。したがって統合すると**「構造クラスタ間の活性差」と「評価系の違い」が完全に交絡し、分離不能になる**。

したがって:

- 旧評価系と新評価系は**別 Endpoint として登録**する
- どちらを解析するかは Run ごとに人間が選ぶ
- 両方を見たい場合は**2 Run 実行し、Finding を突き合わせる**
- 統合を要求された場合は拒否し、理由を提示する

重なりのある化合物が十分に存在する場合に限り、将来の版で橋渡し補正を検討する。0.2.1 では行わない。

Fold change（WT と変異種の比）は `derived` である。EC50(WT) と EC50(mutant) の両方に依存するため、EC50 と Fold change を独立な2軸として扱うと誤った結論を生む。

> **規則**: `derived` Endpoint とその元 Endpoint を、独立した証拠として合算しない。Finding には依存関係を明示する。

### 2.2 `role`

- `primary`: 主たる最適化対象。0.2.1 の単一モードではこれを使う
- `secondary`: 副次的な観点。MPO 拡張時に使う

0.2.1 では人間が `primary` を1つ指定する。複数 Endpoint が登録されていても、解析は指定された1つに対して走る。

## 3. 欠測パターンの扱い 【重要】

### 3.1 問題

Endpoint ごとに測定済み化合物数が異なる（例: A 900、B 500、C 500）。**この欠測は無作為ではない可能性が高い。**

創薬プロジェクトでは通常、一次アッセイで活性が高かった化合物だけが二次アッセイへ進む。この場合:

```text
Fold change が測定されている化合物 = EC50 が良かった化合物
→ Fold change のデータセットは EC50 上位に偏っている
→ その部分集合で EC50 と何かの相関を見ると、範囲制限が入る
```

これは 0.1.x の FF 選抜と**同じ形の罠**である。今度は人間ではなくアッセイの運用が選抜している。

### 3.2 対処

0.2.1 では次を必須とする。

1. **欠測パターンの診断を必ず実行する。** 各 Endpoint について、測定済み群と未測定群で他 Endpoint の分布が異なるかを検定する
2. 系統的な欠測が検出された場合、その Endpoint を使う Finding に `selection_biased` ラベルを付ける
3. Endpoint ごとの有効 N と、その部分集合の活性分布を Finding へ記録する
4. 複数 Endpoint を跨ぐ解析では、**共通して測定されている化合物集合**を明示する

欠測を補完（imputation）しない。測定されていない値を推定して解析へ混ぜることはしない。

### 3.3 診断の出力

```text
Endpoint 欠測診断:
  EP_EC50          900/1000 測定済み
  EP_FOLD_WT_MUT   500/1000 測定済み
    測定済み群の EP_EC50 中央値: 7.9
    未測定群の EP_EC50 中央値:   6.4
    Mann-Whitney p < 0.001
    → 系統的欠測を検出。EP_FOLD_WT_MUT を使う解析には selection_biased を付与
```

## 4. 単一 Endpoint モード（0.2.1 の実装範囲）

指定された `primary` Endpoint に対して L1〜L6 を走らせる。他の Endpoint は次の用途にのみ使う。

| 用途 | 内容 |
|---|---|
| 交絡調整の候補 | 他 Endpoint が交絡している場合の調整軸として（任意） |
| 欠測診断 | 3章の選択バイアス検出 |
| 参考表示 | Finding に関わる化合物の他 Endpoint 値を併記する（解析には使わない） |

最後の項目は安価で有用である。「この変換は EC50 を上げるが、Fold change はこうなっている」を**併記するだけ**なら統計的な主張をせずに人間の判断を助けられる。

## 5. MPO 拡張点（0.2.1 では契約のみ）

将来の横断レンズを次のように予約する。実装は 0.2.1 の範囲外だが、データモデルとスキーマは今から対応させる。

MPO 横断レンズは `M` 接頭辞で区別する（単一 Endpoint レンズの `L` と混同しないため）。

| ID | 名称 | 狙い |
|---|---|---|
| `M1` | トレードオフの解消 | Endpoint A を改善しつつ B を悪化させない変換・領域 |
| `M2` | Endpoint 間の相関構造の条件依存性 | A と B の相関が文脈により変わる（通常は相関するが、ある文脈では独立になる＝両立できる領域） |
| `M3` | Pareto フロンティア | 複数 Endpoint 上で非劣な化合物集合とその構造的特徴 |

`M2` は本質的に L5（符号矛盾）の Endpoint 版であり、統計形式を共有できる。**「通常は活性と選択性がトレードオフだが、この文脈では独立」**という知見は MPO で最も価値が高い部類である。

`M1` は L2 の許容性（第6章）と直結する。「Endpoint A に対して許容的な位置」は、Endpoint B を改善するために自由に使える場所である。

### スキーマ上の準備

- `Finding.claim` は `endpoint_id` の**配列**を持てる（0.2.1 では常に長さ1）
- `scores.frontier_relevance` は Endpoint ごとに計算しうる構造とする
- `triviality.confounders_tested` に他 Endpoint を入れられる

## 6. 許容性（tolerance）という情報

MMP において「変換したが Endpoint に変化なし」は捨てない。

### 6.1 なぜ価値があるか

ある位置の変換が**一貫して Endpoint を変えない**なら、その位置は「活性を損なわずに自由に変更できる」ことを意味する。これは MPO で決定的に有用である。溶解性や代謝安定性を直すために触れる場所が分かる。

### 6.2 ノイズとの区別

ただし「変化なし」を漫然と報告すると、測定ノイズを知見として主張することになり、0.1.x と同じ薄さを招く。区別の鍵は**一貫性**である。

```text
許容性あり    効果が 0 付近に集中し、ばらつきが小さい（分散が小さい）
判定不能      効果が 0 付近だが、ばらつきが大きい（ノイズと区別できない）
```

したがって許容性の検出は「平均が 0 か」ではなく「**分散が小さいか**」で行う。詳細は [`discovery_lenses.md`](discovery_lenses.md) の L2 を参照。

### 6.3 単一 Endpoint モードでの扱い

0.2.1 の単一 Endpoint モードでは、許容性 Finding は `actionability` が低い（次に作るものを直接示さない）。しかし:

- MPO 拡張時に価値が跳ね上がる
- 単一モードでも「この位置は触っても安全」という設計指針になる

したがって検出はするが、既定表示では下位に置き、`tolerance` ラベルで抽出できるようにする。
