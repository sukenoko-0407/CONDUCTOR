## 2. なぜ 0.2.1 を作るか

0.1.11 を実戦投入した結果、**計算は正しく完走するが、人間が注目に値すると感じる知見が出てこない**という問題が確認された。

### 2.1 実戦で観測された症状

実プロジェクト（社内 SAR データ）へ 0.1.11 を適用した結果、次の症状が報告された。

> **計算は正しく完走する。しかし出てくる知見の中身が薄く、人間的に注目に値しないものがほとんどである。**

「既知のことが書いてある」のではなく「**そもそも注目に値しない**」という点が重要である。既知であれば少なくとも正しいが、注目に値しないものは正しくても価値がない。

### 2.2 検証 fixture での観測（参考）

次は ChEMBL JAK2 231化合物の**検証用 fixture** での数値であり、実戦の症状そのものではない。小規模かつ A003 は D001 のみという条件下の値である。ただし後述する構造的欠陥が数値として現れた例として記録する。

| 解析 | 結果 |
|---|---|
| A003 記述子相関 | 868行中、基準通過 0件 |
| A005 予測モデル | `strict_improvement_count: 0`（4 analysis unit、最良でも local R² = 0.176） |
| A006 cliff | 4 unit 中 3件ヒット |
| A008 Top-1 Target | `target_explanation_count: 27` / `observed_improvement_count: 0` / `proposed_improvement_count: 0` / `virtual_candidate_count: 0` |

**この fixture の数値を実戦の症状と混同しない。** 実戦の症状は「0件」ではなく「薄い」である。両者が同じ根本原因から生じているという仮説に立って 2.3 の分析を行うが、fixture の数値は仮説の傍証であって症状の実測ではない。

A008 Top-1 の `improvement: 0` だけは fixture 依存でない構造的帰結である（2.3 (c)）。

### 2.3 根本原因

**(a) 選抜と記述が同じ Endpoint を使っている（循環と範囲制限）**

Cluster は FF ≥ 0.50 で選抜される。つまり Endpoint の上位側に偏った集団だけが残り、unit 内の Endpoint 分散が圧縮される。そこへ A003 は `|r| ≥ 0.60`、A005 は `R² ≥ 0.20` という、範囲を切っていないデータを想定した閾値を当てている。**統計学でいう range restriction により、相関は機械的に減衰する。**

閾値を通過する件数が減るだけでなく、**通過するものの性質が偏る**点が本質である。範囲制限下でなお通過するのは「分散が潰れてなお残るほど強い単純相関」であり、それはほぼ確実に分子サイズか脂溶性の軸である。データ規模が大きければ 0 件にはならないが、**通るものは自明なものに寄る**。実戦の「薄い」はこの形で現れていると考えられる。

**(b) FF ≥ 0.50 という単一ゲートが3つの異なる役割を兼ねている**

1. 計算量の削減
2. 統計的に意味のある候補の絞り込み
3. 人間の関心が高い活性域への誘導

3つを1つのフィルタで同時に行ったことが (a) を生んだ。役割は分解して別の段階へ配置しなければならない。

**(c) Top-1 を MMP Target にする規則が「提案」を数学的にゼロにする**

Top 1 化合物では全 Neighbor が自分より弱いため、`ΔN2T` は全て正になる。よって全件が explanation に分類され、improvement は定義上 0 件になる。実際、同じ Run で Top-1 でない Target（`human_explicit`）は improvement 3件・提案8件を出している。**「次に作るべき化合物」を消していたのは Target 選択規則そのものである。**

**(d) 出力単位が「レポートの節」である**

24 analysis unit × 7 operator ≈ 168 節が、中身の有無にかかわらず必ず埋まる。仕様が「0件でも参考・基準未達を1件表示する」と命じていたのは、格子を必ず埋める設計だったからである。**均一な網羅は、中身が無いときには均一な薄さになる。**

**(e) 仮説形成層が設計思想により禁止されている**

決定論・監査可能性・Template 固定・LLM Vision 禁止は科学的誠実さのための正しい設計だが、**判断が生まれる層をことごとく削っている**。仮説形成は本質的に abduction であり、決定論的パイプラインからは原理的に出てこない。

**(f) 交絡が未調整である**

サイズ・脂溶性で説明できる知見と、そうでない知見が区別されない。「注目に値する」を系が判定する手段が存在しない。

### 2.4 0.2.1 が引き出す教訓

> **絞るべきものと、緩めるべきものを取り違えていた。**

0.1.x は「何を通すか」を厳しく絞り、「どう記述するか」を緩めていた。0.2.1 では逆にする。

| | 0.1.x | 0.2.1 |
|---|---|---|
| 何を計算するか | 絞る（FF≥0.5 で事前選抜） | **緩める**（網羅的に試行） |
| 何を候補にするか | 絞る（単一ゲート） | **緩める**（レンズ別の安価なスクリーン） |
| 何を残すか | 絞る（基準未達は1件のみ） | **緩める**（全て残しラベルを付ける） |
| 型・検定手続き | 緩い（Agent 向け規則を散文で記述） | **厳格**（反証条件必須、テンプレート限定） |
| 引用・監査 | Template hash と件数照合 | **厳格**（全主張に行レベルの引用を強制） |
| 表示 | 全節を必ず表示 | **厳格**（上位K件のみ既定表示） |

### 2.5 【R1】 緩める方向にも上限が要る

R0 のこの診断は正しかった。**しかし「緩める」に上限を書かなかったのが誤りである。**

> **網羅性は無料ではない。試行数は多重比較の族サイズそのものであり、検出力を直接下げる。**

0.1.x は絞りすぎて 0 件だった。R0 の 0.2.1 は緩めすぎて、**族が大きくなりすぎて 0 件になる**。
**同じ結果へ反対側から到達している。**

R1 はこの間に**明示的な位置決め**を入れる（第3.1節）。

## 3. 設計テーゼ

> **条件付けによって初めて現れる構造を、網羅的な試行によって発見する。**

Global なデータが単純な関係性で記述できることは現実にはほぼ無い。しかし**ある局所に条件付けると有用な関係性が現れる**ことがある。

条件の探索空間は人間には広すぎる。機械には可能である。そして CONDUCTOR が使う Local LLM に求めるのは「賢いこと」ではなく「**倦まず大量にこなすこと**」である。

> 1回の深い洞察ではなく、1000回の浅い作業の集積で深さに到達する。

### 3.1 【R1】 網羅性には予算がある

段階Aで「絞りすぎない」ことは正しい。**しかし無制限ではない。**

網羅的な試行には二つの予算があり、**いずれも実行前に検査する**。超過時は `needs_design_review` で停止する。

| 予算 | 制約 | 根拠 |
|---|---|---|
| **計算予算** | 仕事量の事前見積もりが Node 予算以内 | L4 の25万候補、L5 の4,320万 universe を起動前に止める |
| **統計予算** | 族サイズ `n ≤ α (B+1) k_min` | BH と permutation p 値下限から導かれる |

#### 統計予算の導出

BH が順位 k で棄却する条件は `p_(k) ≤ α·k/n`。permutation の p 値下限は `1/(B+1)`。
最良の検定が下限に張り付くとき、BH が棄却できる**最小件数**は

```text
k_min = n / (α (B+1))
```

したがって **k 件の Finding を得たいなら族は `n ≤ α (B+1) k` を満たさねばならない**。

`k_min` は「何件検出できれば設計が成立するか」であり、**人間が決める設計量**である。
0.2.1 では **`k_min = 10`** とする。

#### 実測による確認

| 構成 | 族サイズ | k_min (B=1000) |
|---|---|---|
| R0 仕様（本番規模） | 約 1,155,558 | **23,088 件** |
| R1 仕様（本番規模） | 98 / axis | **2.0 件** |

出典: [`CONDUCTOR_0.2.1_scale_measurement_report.md`](CONDUCTOR_0.2.1_scale_measurement_report.md)

## 4. 中心概念: 条件付けによって現れる構造

0.2.1 の全ての発見レンズは、同じ論理形式を共有する。

```
ある関係性 R は、Global では見えないが、条件 C のもとで現れる（または符号が変わる、または滑らかになる）
```

| R（現れる関係性） | C（条件） | 対応レンズ |
|---|---|---|
| 空間の平坦性（説明力） | 別の特徴量によるフィルタ | L1 |
| 変換の効果 | 非構造的文脈 | L2 |
| 局所の予測可能性 | 近傍 | L3 |
| 未踏領域の有望性 | 近傍の平坦性 | L4 |
| 特徴量-活性相関の符号 | 文脈 | L5 |
| 活性の濃縮 | クラスタ | L6 |
| 置換基序列の転写性 | 骨格 | L7 |

### 4.1 「現れる」の4つの形

条件付けによって構造が現れるとき、その現れ方は4通りある。**4つ全てを検出する。**

| 形 | 内容 |
|---|---|
| 平均のシフト | 条件下で効果の平均が変わる |
| **分散の縮小** | 平均は変わらないが、ばらつきが劇的に小さくなる |
| 符号の反転 | 条件により効果の向きが逆になる |
| 説明力の出現 | 条件下で初めて空間が活性を説明する |

**分散の縮小を落とすと、重要な知見群を取り逃がす。** 「Global では変換の効果が散らばるが、骨格で分けると極端に揃う」という観測は、平均シフト検定では検出されない（層ごとの効果が正負に散れば平均は 0 になる）。しかし実務的には「この変換の効果は骨格に強く依存する」という決定的な知見である。

分散縮小は、平均シフトとは独立に検定する。

### 4.2 新規性の源は2つある

**「文脈が非構造的であること」は新規性の必要条件ではない。** 新規性は次のどちらからでも生じる。

| 源 | 例 |
|---|---|
| 文脈が見えない | 非構造的クラスタで条件付けた結果、効果が現れる |
| 関係性が見えない | 文脈は MCS クラスタ（見える）だが、その中で記述子 F が活性と相関することは見えない |

判定基準は「**その主張が SAR テーブルを眺めて到達できるか**」であり、文脈が構造由来か否かではない。構造クラスタで層別したときに変換の効果分散が縮むことは、目視では到達できない。

### 4.3 なぜ人間に見えないか

レンズごとに異なるが、共通する根は一つである。**条件 C の候補が多すぎて、人間は全ての条件を試せない。** そして条件を試さなければ、Global では打ち消し合って何も見えない。

これが「人間ではできないことをやる」の具体的な内実である。人間より優れた推論をするのではなく、**人間が試す気にならない回数の条件付けを試す**。

## 5. アーキテクチャ: 6 Phase

```text
Phase 1  表現生成          全 Description を計算し、解釈可能性でタグ付けする
Phase 2  文脈の語彙構築     条件のカタログを作り、各条件を解釈可能な語へ翻訳する
Phase 3  関係性の網羅的評価  7レンズ × 条件カタログを安価な統計でスクリーンする
Phase 4  スコアリング       足切りと順位付けを行う
Phase 5  深堀              上位 Finding をテンプレート検定で再帰的に掘る
Phase 6  統合と報告        Finding を連結して統合 narrative を作り、引用整合性を検証する
```

### Phase 1: 表現生成

全 Description を計算する。各空間に **解釈可能 / 非解釈可能** のタグを付与する（第7章）。あわせて環系を同定し、変換の3クラス（第8.1節）に必要な fragmentation を作る。

Program 別 Description Database による再利用（0.1.10 の設計）は健全なので技術的に流用する。同一 Program・同一 calculation_version・同一計算条件・同一 canonical SMILES の一致で再利用し、miss だけを計算する。

旧Description Skillのidentity schemaへは決定論的bridgeを介して接続する。Database登録は既定で全feature有限を要求するが、D015/D016 Mordredは構造上定義されない希少元素featureのnullを許容し、行の50%以上かつ1件以上が有限の場合だけ登録する。全feature非有限または計算失敗行は登録しない。D015/D016のこの契約は`calculation_version=2`とする。

### Phase 2: 文脈の語彙構築

条件 C の候補カタログを作る。語彙は4種類。

| 種類 | 生成元 | 概数 |
|---|---|---|
| クラスタ所属 | average-linkage 凝集型 × 全 Description × クラスタ数 grid | 較正実測で約 200 |
| 特徴量の範囲分割 | 解釈可能特徴量の分位点分割 | 数百 |
| 骨格クラス | Murcko / MCS / BRICS / RECAP | 数十 |
| 活性域 | frontier / 中域 / 低域 | 数個 |

各条件は、報告可能になる前に**解釈可能な語へ翻訳**されなければならない（第7章）。翻訳できない条件は文脈としては使えるが、Finding の説明には使えない。

### Phase 3: 関係性の網羅的評価

7つのレンズそれぞれが、自前の安価な統計スクリーンを持つ。**条件付け深度は 1 とする**（単一条件のみ）。

**【R1】** この段階では絞りすぎないが、**第3.1節の2つの予算を実行前に検査する**。
候補プールは数百〜数千件を想定する。**数十万件になる構成は設計の誤りであり、実行前に停止する。**

### Phase 4: スコアリング

二段構えとする。

```text
足切り:  統計的強度（型内パーセンタイル）× 頑健性（bootstrap 安定性）
順位:    非自明性 × 実行可能性 × frontier 近接度
```

**frontier 近接度は事前フィルタではなく事後の重みである。** 統計は全域データで計算するため範囲制限を受けず、優先順位付けだけが人間の関心に沿う。これにより「7→8 の変換それ自体に関心は無いが、その証拠を pIC50 9 の化合物へ適用できるなら価値がある」が表現できる。**証拠の活性域と適用先の活性域を分離する。**

### Phase 5: 深堀

上位 K 件の Finding を、固定テンプレート集合による子問いで再帰的に掘る。子問いは自由記述させない。

状態は4つ。`SURVIVED` / `WEAKENED`（境界条件の発見＝主張の精緻化であり、悪い結果ではない） / `REFUTED` / `INCONCLUSIVE`。

予算は 深度 ≤ 3、分岐 ≤ 3/node、1 Finding あたり検定実行 ≤ 15回。

### Phase 6: 統合と報告

エンティティを共有する Finding を連結し、連結成分ごとに統合 narrative を作る（第9章）。木構造のダンプではなく、**引用付きの短い文章**とする。全主張の引用（compound_id, pair_id, 検定名, p値）の整合性を機械検証し、不整合があれば報告を失敗させる。

## 6. 出力単位は Finding である

0.1.x では出力単位が「analysis unit × operator の節」だった。0.2.1 では **Finding** とする。

Finding は主張・検定・反証条件・自明性判定・引用を持つ構造体であり、互いに順位を競う。良い Finding が3件ならレポートは3件になる。**格子を埋めない。**

```text
Finding #3   [notable] 交絡調整後も残存 / frontier 到達性 高

主張     変換 [4-F-phenyl → 4-CF3-phenyl] は、文脈 C007-12 に属する化合物でのみ活性を上げる
         C007-12 内: 中央値 +0.62 log (n=7, 方向一致 7/7)
         他の文脈  : 中央値 +0.03 log (n=11, 方向一致 5/11)
         交互作用 p=0.003 (BH q=0.04)

文脈     C007-12 は D019 (xTB) 由来クラスタ。Murcko 骨格では3種類に分かれており、
         構造分類では一つの群として見えない。
         翻訳: 芳香環の静電ポテンシャル分布が特徴（解釈可能記述子による判別）

自明性   ΔlogP +0.9。脂溶性で調整後も +0.48 log 残る → 脂溶性では説明できない

到達性   効果を受けた7化合物のうち5個が pIC50 8.5 以上（frontier 上）

次の一手 同じ文脈に属し、この変換が未適用の化合物: CPD-0231 (8.6), CPD-0447 (8.4)
```

**「なぜ効いているのか」と「次に何を作るか」が一つの Finding の中に同居する。** 0.1.x では前者が A003/A005、後者が A008 に分かれており、しかも両方ゼロ件だった。

詳細は [`design/finding_model.md`](design/finding_model.md)。

## 7. 特徴量空間の二役割

**空間には「文脈を定義する役割」と「説明する役割」があり、後者だけが解釈可能性を要求される。**

| 役割 | 要求 | 使える空間 |
|---|---|---|
| **文脈定義** | 再現性のある群を作れること | 全空間（Fingerprint 可） |
| **説明** | 人間が読んで意味が取れること | 解釈可能空間のみ |

Fingerprint 空間で条件付き平坦性が見つかっても、`morgan_bit_1417` が効いていると言われて人間に使える情報にはならない。しかし**群を定義する道具としては Fingerprint は有効**である。

したがって規則を置く。

> **すべての Finding は、解釈可能な説明成分を最低1つ持たねばならない。**
> Fingerprint 等で定義された文脈は、報告前に解釈可能な語へ**翻訳**する。翻訳できない文脈を含む Finding は報告しない。

翻訳は、文脈への所属を解釈可能記述子から予測する小モデルを当て、判別に寄与する記述子を提示することで行う。これ自体が小さく反復可能なタスクであり、Local LLM の「愚直に大量」方針に適合する。

詳細は [`design/feature_space_roles.md`](design/feature_space_roles.md)。

## 8. 7つの発見レンズ

実データのドライラン（[`design/calibration_results.md`](design/calibration_results.md) 第8章）で
各レンズの実効性を測定した。enrichment は実データ候補数 / 骨格内並べ替え帰無の候補数。

| | レンズ | 単位 | enrichment | 扱い |
|---|---|---|---|---|
| **L2b** | **フラグメント寄与 × 文脈** | フラグメント | **2.1〜2.5** | **主力** |
| **L5** | 文脈間の符号矛盾 | 特徴量 × 文脈 | **1.8〜2.2** | 有効。**【R1】比較単位を「文脈 vs 軸内補集合」へ変更し、族を axis 別に分割する** |
| **L1b** | 条件付き平坦性（クラスタ水準） | 空間 × 条件 | 1.3〜1.5 | 残す。歩留まりは悪いが信号はある |
| **L4** | 未踏の有望領域 | 空白（領域） | 未測定 | 残す。L2b の変換 DB に依存 |
| **L7** | 骨格 × 置換基の交互作用 | 系列 | 未測定 | 補助。実働は共通 R 基 ≥5 の 43 系列ペア |
| L2a | 変換 × 文脈 | 辺（変換） | — | 繰り返しのある 252 変換に限定 |
| ~~L1a~~ | 空間水準の説明力 | — | 不在 | **診断指標へ降格** |
| ~~L3~~ | 局所期待からの逸脱 | 点 | **1.0** | **信号なし。診断指標へ降格** |
| ~~L6~~ | 活性濃縮クラスタ | 群 | **1.0** | **信号なし。診断指標へ降格** |

L4はone-step生成全件を無上限に再記述しない。候補Description前に到達経路と観測pair支持で決定論的に順位付けし、既定100候補、Tier 1/2再記述900行を上限とする。さらにDescriptionのcost class別重みを使って予定cost unitsを評価し、10,000 unitsを上限とする。予定行数またはcost unitsが上限を超える設定では計算開始前に`needs_design_review`で停止する。

### 8.0 レンズは骨格主効果に直交していなければならない 【実測から導かれた設計原理】

ドライランで成否がきれいに分かれた。

| レンズ | 骨格主効果との関係 | enrichment |
|---|---|---|
| **L2b** | **系列平均を引く = 骨格効果を明示的に除去** | **2.5** |
| L5 | 文脈内相関どうしの比較 = 部分的に骨格を吸収 | 1.8〜2.2 |
| L1b | 文脈内の平坦性。文脈は骨格と重なる | 1.3〜1.5 |
| L3 | 近傍逸脱。近傍は骨格と重なる | 1.0 |
| L6 | クラスタの活性濃縮 ≒「良い骨格」の検出 | 1.0 |

> **レンズの設計基準は「条件付けで構造が現れるか」だけでは足りない。**
> **「骨格が既に与える情報を超えているか」でなければならない。**

L6 の帰無分布を2通りで計算すると決定的である。全体並べ替え（骨格構造を壊す）では帰無 ≈ 0、骨格内並べ替え（骨格構造を保つ）では帰無 ≈ 観測。**L6 が検出しているのは「この骨格は活性が高い」であり、化学者が既に知っていることである。**

L6 は 0.1.x の唯一の入口だった。**0.1.x で有用な知見が出なかった直接の理由がこれである可能性が高い。**

L1 が中心概念の最も直接的な表現である。L4 が成立する土台も提供する。

**L1 は2水準に分ける。**

| 水準 | 主張 | 検定単位 | 検定数 |
|---|---|---|---|
| L1a | 空間 A × クラスタリング B の**すべての**クラスタで関係性が見える | (空間, クラスタリング) | 約100 |
| L1b | クラスタの**1個または一部**で関係性が見える | (空間, クラスタ) | 数千 |

L1a が成立するなら特徴量 A 自体が Endpoint 説明能力を持つ。

**実データ計測（[`design/calibration_results.md`](design/calibration_results.md) 第3章）により、L1a は全空間で不在と確定した。** best_min_lam の最大値が負であり、どの特徴量も全クラスタでは活性を説明しない。したがって **L1a をレンズから外し、診断指標へ降格する**。検定約100回で何も生まないものをレンズとして保持しない。ただし「どの特徴量も全域では活性を説明しない」という事実は報告価値があるため、診断行として残す。

一方 **L1b は成立した**（best_max_lam の最大値が 0.8 以上）。同一の空間・同一のクラスタリングの中に λ > 0.8 のクラスタと λ < 0 のクラスタが同居しており、「この局所でだけ関係が見える」が実データで起きている。

設計段階で「最も価値が高い型」と位置づけた **L1a 不成立かつ L1b 成立** が、例外ではなく**支配的なパターン**であることが確認された。これが深堀の主要な起点になる。

L6 は捨てない。**7つある入口の1つ**として残す。0.1.x での問題は FF≥0.5 が間違っていたことではなく、**それが唯一の入口だったこと**である。

### 8.1 変換の3クラス

標準的な MMP は非環結合の 1-cut / 2-cut に限られる。しかし**実プロジェクトでは環構造そのものを様々なパターンで試す**ことが多く、環が変われば MMP は別コアと認識する。標準 MMP のままでは、**プロジェクトが実際に探索している軸を見られない**。

したがって変換を3クラスへ拡張する。

| クラス | variable | cut 数 |
|---|---|---|
| 末端置換 | 末端フラグメント | 1 |
| リンカー置換 | 2点接続の非環部分 | 2 |
| **環系置換** | **環系全体** | **N（環系の接続数）** |

環系置換は、環系と分子の残りを繋ぐ結合（exocyclic bond）だけを切る。**環結合そのものは切らない**ため構造的妥当性は保たれる。cut 数の上限 2 という制約は外し、環系の接続数から決める。

### 8.2 平坦と Cliff は両方に価値がある

局所平坦性 λ は空間を捨てる道具ではなく、**二分して別経路へ振り分ける道具**である。

| λ | 意味 | 行き先 |
|---|---|---|
| 高い（平坦） | 期待値が語れる | L1、L3（逸脱）、L4（未踏領域） |
| **低い（Cliff）** | **構造要因が確実に存在する。情報が濃い** | **L2（MMP・変換解析）** |

Cliff は化学者が実際に行っている作業そのものである。構造の似た化合物を並べ、Endpoint を大きく動かす構造要因を探る——これは暗黙の MMP 解析であり、**Cliff はその入口**にあたる。**平坦であることがすべてではない。**

#### Cliff は構造空間でのみ列挙する

Cliff が情報を持つのは「近い」が**抽出可能な差分**を意味するときだけである。

| 空間 | 「近い」の意味 | 差分を抽出できるか |
|---|---|---|
| 構造空間 | 部分構造を共有している | **できる。**「Cl → OMe」と名指せ、他へ適用できる |
| 非構造空間 | 計算された性質の値が近い | **できない。** 構造は全く違いうる |

非構造空間の Cliff は「性質は近いが活性が違う」という事実しか与えず、**何を変えればよいかを言えない**。さらに**その非構造空間が全体として Cliff 的なら、個々の Cliff は例外ですらなく常態である**。例外でないものに情報は無い。高次元記述子空間では距離集中により最近傍自体が信頼できないという問題も重なる。

したがって **Cliff の列挙は構造空間に限る**。非構造空間の λ が低いことは「その空間はそこでは活性を説明しない」という情報であり、L1/L3/L4 のゲートとしてのみ使う。

これは L3 で「平坦な近傍でのみ期待値を語る」とした規律を、Cliff 側にも対称に適用したものである。

#### 構造性は解釈可能性とは独立の軸である

| 軸 | 問い | 用途 |
|---|---|---|
| 解釈可能性（Tier 1/2/3） | 人間が読んで意味が取れるか | **説明**に使えるか |
| **構造性**（structural / non-structural） | 近さが抽出可能な構造差分を意味するか | **Cliff 抽出**に使えるか |

2軸は直交する。ECFP4 は Tier 3（説明不可）だが構造空間（Cliff 抽出可）。RDKit 2D は Tier 1（説明可）だが非構造空間（Cliff 抽出不可）。

#### 判定は操作的基準で行う

> **Cliff が L2 の材料になる条件は「そのペアから変換が抽出できること」である。**

```text
構造空間で Cliff 検出 → 変換の抽出を試みる → 抽出できたものだけ L2 へ
→ その変換を全ペアで検定 → 再現すれば Finding
```

単一の Cliff ペアを知見として主張しない。1ペアの活性差は測定誤差に丸ごと晒される。**Cliff は仮説の種であり、検証は変換が現れる全ペアで行う。** Cliff 起点は変換の網羅列挙と**並行して**走らせる。

congeneric データでは構造空間の λ は全体的に低く、Cliff は大量に出る。優先順位は `Endpoint 差 × 構造的近さ × 抽出された変換の他ペアでの出現数` とし、**第3項を最重視する**。1組しか現れない Cliff はノイズの可能性が高い。

実データでの抽出率は **0.44**（Tanimoto ≥ 0.75, |Δ| ≥ 1.0 IQR）。Cliff の 56% は構造が離れすぎて変換にならず、抽出フィルタが実際に機能している。

**Cliff の Endpoint 差閾値は IQR 基準ではなく推定ノイズ SD の倍数（3 σ_diff）で定義する。** IQR はデータセットごとに2倍以上変動し、閾値の基準として不適切である。詳細は [`design/calibration_results.md`](design/calibration_results.md) 第2章。

### 8.3 骨格比較は3層で行う

環系置換ペアは「環**以外**が完全一致する」場合しか成立しない。実際には環を変えると側鎖も少し変わるため、厳密一致ペアは限られる。粒度の異なる3層を並行して走らせる。

| 層 | 単位 | 問い | 被覆 |
|---|---|---|---|
| 環系置換 | ペア（厳密一致） | 環を変えると活性はどう変わるか | 狭い・精密 |
| **Core 類似度** | **ペア（類似 core 間）** | **同じ置換は類似 core を跨いで転写するか** | 中間 |
| L7 骨格 × 置換基 | 系列（共通 R 基 m 個以上） | 骨格間で置換基の序列は転写するか | 広い・粗い |

中段は 0.1.11 が持っていた **Attachment 制約付き MCS ＋ Tanimoto による Similar core** の機構を継承する。ピリジン／ピリミジンのような環バリアント間でも対応を取れるため、環構造探索の比較に直接効く。

ただし**出力の仕方は変える**。0.1.11 は類似 core の Evidence を並べて人間に解釈を委ねており（Target 1件あたり canonical evidence 3,060行）、これが認知負荷の主因だった。0.2.1 では **core 類似度クラスを条件 C の一種として L2 の交互作用機構へ乗せ**、人間には結論だけを返す。

```text
類似度クラスを跨いで効果が一定      → 変換は core に依存しない汎用変換
類似度を緩めると効果が消える／散る  → 変換は特定 core に固有
```

**機構は流用し、判断を機械側へ移す。** これが 0.1.11 の認知負荷への回答である。

詳細は [`design/discovery_lenses.md`](design/discovery_lenses.md)。

## 9. 統合への道筋

個別 Finding が並ぶだけでは「統合的な知見」にならない。Phase 6 の統合は**機械的な手順**として定義する。

### 9.1 機構: エンティティ共有グラフ

Finding は必ず具体的なエンティティ（文脈 ID、骨格、変換、化合物 ID、特徴量）を参照する。**同じエンティティを参照する Finding 同士を辺で結び、連結成分を1つの物語として扱う。**

```text
1. 各 Finding が参照するエンティティを抽出する
2. エンティティを共有する Finding 間に辺を張る
3. 連結成分を取り出す
4. 成分ごとに LLM が1段落の統合 narrative を書く（引用強制）
```

LLM に与えるのは「エンティティを共有する3〜5件の Finding」という小さな入力であり、**発見ではなく接続のタスク**になる。27B クラスで扱える大きさに保たれる。

### 9.2 統合の例

架空の数値による例。プロジェクトが複数の環構造を試している状況を想定する。

```text
Phase 3〜5 が出した個別 Finding:

  F-012 (L7)  骨格 P と骨格 Q で置換基の序列が逆転（共通 R 基 8、Spearman ρ = −0.62）
  F-047 (L1)  骨格 Q 系列に限ると、xTB 由来の電子的指標が活性を説明する（λ 0.11 → 0.71）
  F-089 (L2)  変換 [Cl → OMe] は骨格 Q でのみ活性を上げる（分散縮小により検出）
  F-103 (L4)  骨格 Q × 電子供与基の近傍に未踏領域。到達経路あり

共有エンティティ: 骨格 Q（4件すべて）

Phase 6 の統合 narrative:

  骨格 P と Q では置換基 SAR の序列が逆転している (F-012)。Q 系列に限ると
  電子的指標が活性を説明しており (F-047)、これと整合して、電子供与基への変換
  Cl → OMe は Q でのみ効く (F-089)。Q × 電子供与基の組合せには未試験領域が
  残っており (F-103)、CPD-xxxx への [変換] が次の候補となる。
```

4つのレンズが別々に出した Finding が、**骨格 Q という共有エンティティによって1つの説明へ収束する**。個別 Finding は「なぜ効くか」の断片だが、連結すると機構の仮説になる。

### 9.3 なぜこれが 0.1.x でできなかったか

0.1.x の出力単位は analysis unit × operator の節だった。**節は互いに参照し合わない。** A003 の結果と A008 の結果を結ぶ構造がなく、統合は読み手の頭の中でしか起きなかった。

Finding を単位にし、エンティティ参照を必須フィールドにすることで、**統合が機械的に実行可能になる**。

## 10. LLM の分業線

| 層 | 担当 | 理由 |
|---|---|---|
| 発見・順位付け | **決定論層** | 統計と閾値の仕事であり、そもそも LLM の仕事ではない |
| 説明・接続・深堀の分岐選択 | **LLM** | 言語の仕事。27B クラスで射程内 |

0.1.x では LLM に「168節の定型レポートを読んで意味を抽出せよ」と頼んでいた。これは**発見**を任せており、27B には重い。0.2.1 では決定論層が発見と順位付けを終えた後、LLM には「この5件の Finding を化学的に説明し、つなぎ、次の一手を書け」と頼む。**articulation** を任せる。

**I001 の出力が薄かったのは、I001 の入力が薄かったからでもある。** 中身のない168節を渡されて深い考察を書ける言語モデルは存在しない。上流を直せばモデルを替えずに出力が濃くなる可能性が高い。

監査可能性は**決定論からではなく、引用の検証可能性から**得る。LLM に判断させつつ、全主張が決定論層の行を引用することを強制し、引用整合性を機械検証する。引用強制は監査のためだけでなく、**弱いモデルの脱線を防ぐ拘束具**として実用的に効く。

詳細は [`design/llm_operating_contract.md`](design/llm_operating_contract.md)。

### 10.1 プロンプトは二層に分ける

0.2.1 のプロンプトは次の二層を持つ。

| 層 | 利用者 | 目的 |
|---|---|---|
| 運用プロンプト | 人間 → Main Agent | Preflight、新規Run、再開、状態確認、監査を一意に依頼する |
| 内部タスクプロンプト | offline provider → Local LLM | Phase 5/6 の限定された判断と言語化を、固定JSON契約の内側で実行する |

正式な文面とplaceholderは [`prompt/CONDUCTOR_0.2.1_prompts.md`](prompt/CONDUCTOR_0.2.1_prompts.md) を正本とする。運用プロンプトは実行権限の範囲を明示し、read-only依頼をRun進行やDatabase更新へ拡張してはならない。内部タスクプロンプトは `select_deep_dive`、`summarize_deep_dive`、`compose_component_narrative` の3種類だけを許可する。

### 10.2 Local LLMの出力境界

providerはJSONL stdin/stdoutで通信し、1 requestにつきschema-validなJSON objectを1行だけ返す。LLMはevidence外のID、数値、引用、検定を作らず、根拠不足時には空の選択または`null` narrativeを返す。深堀状態は決定論層が判定し、LLMへ委ねない。narrative中の引用は `[[citation_id]]` 形式とし、Phase 6で本文、`citations`配列、引用行の値を機械照合する。

プロンプト文書の存在だけではproviderの実装完了を意味しない。本番Runの前に `llm.command` を設定し、3タスク全てのschema、timeout、終了code、stdout純度をprobeしなければならない。

参照構成は、Ubuntu CPU機上の`CONDUCTOR_modules/local_llm_provider/provider.py`と、別GPU機上の承認済み`vllm serve` OpenAI互換APIの組合せとする。Description計算、統計検定、template実行、状態判定、引用検証はCPU機で行い、GPU serverはLLM推論だけを担当する。擬似OpenAI互換server testは通信契約だけを確認するものであり、CPU機から実modelへ行う3タスクprobeを置き換えない。

## 11. Endpoint と MPO 対応

> **単一 Endpoint で確実に仕事ができることを最優先とする。ただし多目的最適化（MPO）へ拡張できる構造で作る。**

0.2.1 が実際に届けるのは単一 Endpoint の解析である。しかし Endpoint を「1本の列」として設計へ埋め込むと、後から MPO を載せる際に全面改修になる。したがって**データモデルは最初から複数 Endpoint を表現できる**ものとし、解析側は 0.2.1 では単一 Endpoint モードだけを実装する。

| | 0.2.1 で実装 | 拡張点として確保 |
|---|---|---|
| Endpoint レジストリ（複数登録） | ✓ | — |
| 単一 Endpoint レンズ（L1〜L7） | ✓ | — |
| Finding の Endpoint 参照 | ✓ 配列だが長さ1 | 複数参照 |
| 横断レンズ（M1〜M3） | 契約のみ定義 | 実装 |

### 11.1 欠測パターンの診断は必須とする

Endpoint ごとに測定済み化合物数が異なる場合、**その欠測は無作為ではない可能性が高い**。創薬プロジェクトでは通常、一次アッセイで活性が高かった化合物だけが二次アッセイへ進むためである。

```text
副次 Endpoint が測定されている化合物 = 主 Endpoint が良かった化合物
→ 副次 Endpoint のデータセットは主 Endpoint の上位に偏る
→ その部分集合での解析に範囲制限が入る
```

**これは 0.1.x の FF 選抜と同じ形の罠である。** 今度は人間ではなくアッセイの運用が選抜している。したがって欠測パターンの検定を必須工程とし、系統的欠測が検出された Endpoint を使う Finding には `selection_biased` ラベルを付ける。欠測の補完は行わない。

### 11.2 許容性（tolerance）

MMP において「変換したが Endpoint に変化なし」は捨てない。その位置が活性を損なわずに変更できることを意味し、MPO で決定的に有用である。

ただし判定基準は「平均が 0 であること」ではなく「**分散が小さいこと**」とする。一貫性を要求しなければ測定ノイズを知見として主張することになる。

詳細は [`design/endpoint_model.md`](design/endpoint_model.md)。

## 12. 計算資源と並列化

**相当量の計算リソース（多コア CPU を長時間）が利用可能であることを前提とする。** 網羅探索を成立させるため、並列化を設計の中心に置く。

### 12.1 並列化の単位

| 工程 | 並列化の単位 | 性質 |
|---|---|---|
| Phase 1 表現生成 | 化合物 × Description | 完全並列 |
| Phase 2 文脈構築 | Description × Clustering 手法 | 完全並列 |
| Phase 3 L1 帰無分布 | 文脈 × 空間 × 反復 | **完全並列。最大の負荷かつ最も並列化の利く箇所** |
| Phase 3 L2 | 変換 | 完全並列 |
| Phase 3 L3 | 空間（近傍計算は空間ごとに1回） | 完全並列 |
| Phase 3 L5 | 分割軸 | 完全並列 |
| Phase 4 スコアリング | Finding | 完全並列 |
| Phase 5 深堀 | Finding 間は並列、Finding 内の木は逐次 | 部分並列 |
| Phase 6 報告 | — | 逐次 |

### 12.2 律速はどこか

決定論層は並列化により容易にスケールする。**律速は Local LLM の呼出である。** 単一モデルで逐次処理されるため、コア数を増やしても短縮されない。

したがって:

- LLM 呼出回数を設計段階で見積もり、抑制する（[`design/llm_operating_contract.md`](design/llm_operating_contract.md) 3章）
- 決定論層で済むものを LLM へ回さない
- LLM 呼出は Phase 5 と 6 に集中させ、Phase 1〜4 では使わない

### 12.3 中間成果物の再利用

網羅探索は繰り返し実行される（閾値の調整、Endpoint の切り替え）。再計算を避けるため、次を永続化して再利用する。

- Description（Program 別 Database。0.1.10/0.1.11 の実装を変換せず流用）
- 文脈カタログと翻訳結果
- MMP canonical database
- 局所平坦性 λ（空間 × 化合物）
- L1 の帰無分布（文脈 × 空間）

Endpoint を変更した場合、**構造に依存する成果物（Description、文脈、MMP pair、λ の空間構造）は再利用でき、Endpoint に依存する量だけ再計算する**。この分離を Artifact 設計へ反映する。

Description Databaseのcache hitには、同一Program、同一compound ID、同一canonical SMILES、同一`calculation_version`、同一calculation signatureを要求する。同一ID・異構造はfail-fastとする。Gobbi Pharm2DのSVDのようなbatch-dependent計算ではdataset signatureも一致しなければならない。0.1.xのRun state、Execution Request、Finding、検定結果、narrativeは再利用対象に含めない。

## 13. 決定事項

本書で確定した設計判断を列挙する。実装状況と正式受入前の残件はStage 11実装報告書を正とする。

1. 出力単位を「レポートの節」から **Finding** へ変更する。格子は埋めない。
2. 発見レンズを6つ用意する。FF 濃縮（L6）は唯一の入口ではなく6分の1とする。
3. 特徴量空間に **文脈定義用** と **説明用** の二役割を定義し、説明用のみ解釈可能性を要求する。
4. すべての Finding は解釈可能な説明成分を最低1つ持つ。翻訳できない文脈を含む Finding は報告しない。
5. FF≥0.5 の単一ゲートを **段階A（レンズ別スクリーン）/ 段階B（共通スコアリング）/ 段階C（frontier 重み）** へ分解する。
6. **frontier 近接度は事前フィルタではなく事後の重み**とする。統計は全域データで計算する。
7. **条件付け深度は 1 とする。** 単一条件のみを文脈として使い、条件の組合せ（C₁ ∧ C₂）は作らない。較正データで深度1の文脈が 270 あり重複排除後でも十分な数が取れること、深度2は多重比較の族が組合せで増える一方で有効性が未測定であることによる。**深度2は 0.2.2 の検討事項とする。**
8. Finding は **反証条件を必須**とする。反証条件を書けない仮説は検定前に棄却する。
9. 深堀の子問いは**固定テンプレート集合からの選択とパラメータ埋め**に限定する。自由記述させない。
10. 深堀の状態は `SURVIVED` / `WEAKENED` / `REFUTED` / `INCONCLUSIVE` の4つ。`WEAKENED` は主張の精緻化であり失敗ではない。
11. 深堀予算は 深度 ≤3、分岐 ≤3/node、検定実行 ≤15回/Finding。
12. LLM の担当は **説明・接続・分岐選択**のみ。発見と順位付けは決定論層が行う。
13. 監査は**引用整合性の機械検証**による。Template hash による固定は用いるが、判断層の監査はそれに依存しない。
14. **何も削除しない。** 足切りで落ちた候補も、既知確認とラベルされた Finding も、理由付きで追跡可能に残す。表示は上位K件が既定。
15. 既知の知見が Finding として出ることを許容し、`known_confirmed` とラベルする。系の較正が効いていることの証明として扱う。
16. 各 Skill は Pixi (`env/pixi.toml`) で自己完結する。
17. ローカル平坦性（SALI）は**空間単位ではなく近傍単位**で判定する。平坦な近傍は L3/L4 の土台に、鋭い Cliff は L2 の材料に振り分ける。
18. **条件付けの現れ方を4形式（平均シフト / 分散縮小 / 符号反転 / 説明力出現）とし、全て検出する。** 特に分散縮小は平均シフト検定では検出されないため独立に検定する。
19. **新規性の判定は「SAR テーブルを眺めて到達できるか」で行う。** 文脈が構造由来か否かでは判定しない。
20. **データモデルは複数 Endpoint を表現できる構造とし、0.2.1 の解析は単一 Endpoint モードのみ実装する。** MPO 横断レンズ（M1〜M3）は契約のみ定義する。**1 Run = 1 Endpoint** とし、構造依存の成果物のみ Run 間で再利用する。
21. **Endpoint の欠測パターン診断を必須工程とする。** 系統的欠測が検出された Endpoint を使う Finding には `selection_biased` を付与する。欠測補完は行わない。
22. MMP の「変化なし」を捨てず、**分散が小さい場合に限り**許容性（`tolerance`）として保持する。
23. L6 の Favorable 定義は Global Endpoint の上位20%のままとする。
24. LLM 出力の再現性（temperature / seed の固定）は要件としない。
25. **並列化を設計の中心に置く。** 相当量の計算リソースが利用可能であることを前提とし、律速となる LLM 呼出は Phase 5/6 に限定する。
26. 置換基の電子効果は Hammett 定数と部分電荷により**機械的に算出する**。人間による定義提供は求めない。
27. プロジェクト固有 SMARTS パターンは**相互排他を前提としない**。包含関係を機械検出し、階層を考慮した多重比較補正を行う。
28. **変換を3クラス（末端置換 / リンカー置換 / 環系置換）へ拡張する。** 環系置換は exocyclic bond のみを切り、cut 数の上限 2 を撤廃する。3クラスは集計・Finding・表示を分離する。
29. **L7（骨格 × 置換基の交互作用）を追加する。** ペア単位の L2 と系列単位の L7 を相補的に併用する。
30. **Phase 6 の統合はエンティティ共有グラフによる。** 同じエンティティを参照する Finding を連結し、連結成分ごとに統合 narrative を作る。
31. **重なりの無い評価系カラムを1つの Endpoint へ統合しない。** 橋渡しできる化合物がないまま連結すると、評価系の違いと構造の違いが分離不能な形で交絡する。
32. **既定の上位表示件数 K = 10。** 深堀込みで1件あたりの分量が大きくなるため、30件は多すぎる。
33. 前処理（塩除去、互変異性、中和、立体）は人間の責務とする。同一 ID に異なる構造が与えられた場合は fail-fast とする。
34. **L1 を2水準（L1a 空間水準 / L1b クラスタ水準）に分ける。** 実データ計測により **L1a は不在と確定したため、レンズから外して診断指標へ降格する**。多重比較補正は水準ごとに独立に行う。**L1a 不成立かつ L1b 成立**が支配的パターンであり、これを最も価値の高い型として扱う。
35. **λ が低い（Cliff）近傍を捨てない。** 平坦側は L1/L3/L4 へ、Cliff 側は L2 へ振り分ける。**Cliff は仮説の種として使い、検定は変換が現れる全ペアで行う**（発見の起点と検証の母集団を分ける）。Cliff 起点は変換の網羅列挙と並行して走らせる。
35b. **Cliff の列挙は構造空間に限る。** 非構造空間では Cliff を列挙しない（差分を抽出できず、空間が全体として Cliff 的なら個々の Cliff は例外ですらないため）。最終判定は操作的基準、すなわち**そのペアから変換が抽出できるか**による。
35c. **構造性（structural / non-structural）を解釈可能性 Tier とは独立の軸として定義する。** Tier は説明に使えるかを、構造性は Cliff 抽出に使えるかを決める。ECFP4 は Tier 3 だが構造空間、RDKit 2D は Tier 1 だが非構造空間である。
36. **特徴量 Database は 0.1.11 の実装をほぼそのまま転用する。** 0.1.11 → 0.2.1 は大きな仕様変更だが、Description Database は設計・実装とも健全であり、再構築しない。
37. **全閾値は実データ較正に基づく**（[`design/calibration_results.md`](design/calibration_results.md)）。測定 σ ≈ 0.10、σ_diff ≈ 0.14、信頼性 0.86。単一ペアの neutral 判定は \|Δ\| < 0.28（2σ_diff）、Cliff の Endpoint 差下限は \|Δ\| ≥ 0.42（3σ_diff）。**Cliff 閾値を IQR 基準からノイズ基準へ変更する。**
38. **帰無分布は骨格内並べ替えを既定とする。** Murcko 骨格の ICC が 0.44、実効標本サイズが化合物数の 0.25〜0.71 倍であり、骨格を跨いだ並べ替えは骨格主効果まで帰無側へ混ぜて帰無分布を過度に広げる。全レンズへ適用する。
39. **L2 の分析単位を2つに分ける。** 実データで変換はほぼ繰り返されない（TERM 9,548ペアが7,300種類、3ペア以上はわずか252種類）。**L2a 変換単位**は繰り返しのある頭（252件）に限定し、**L2b フラグメント寄与（Free-Wilson 分解）**を主力とする。後者はペアの繰り返しを要求せず、環の比較にも適用できる。
39b. **並べ替え単位は解析の条件付け単位に合わせる。** L2 は系列内、L1b/L6 は骨格内、L3/L4 は全体。単一の万能ブロックは存在しない（ICC 最大の fp_cluster_t0.8 は 2.2化合物/ブロックで自由度が枯れる）。
39c. **Cliff の Tanimoto 下限は 0.75 に据え置く。** 0.85 へ上げても抽出率は 0.44→0.46 とほぼ改善せず件数だけ失う。抽出失敗の原因は距離ではなく MMP 分解不能である。
39d. **L7 は補助レンズに降格する。** 共通 R 基 ≥5 の系列ペアは 43 件のみ。`pair_r3 = 2,085` は Spearman が3点では検出力を持たないため実働範囲ではない。骨格比較の主力は L2b とする。

42. **内部LLM taskは3種類に限定する。** `select_deep_dive`、`summarize_deep_dive`、`compose_component_narrative`以外を0.2.1 providerへ追加せず、根拠不足時の空/null応答を正当な結果とする。

## 14. 0.1.x から技術的に流用する資産

思想は引き継がないが、以下は実装資産として価値がある。

| 資産 | 流用先 | 理由 |
|---|---|---|
| **Description Database（Program 別 SQLite、`calculation_version` による再利用判定）** | Phase 1 | **ほぼそのまま転用する。** 設計・実装とも健全であり再構築しない。同一 ID・異構造の fail-fast、監査付き invalidate も含めて継承 |
| MMP canonical database（0.1.11 Mode II） | L2 の土台 | Target 非依存・immutable な設計は正しい。Evidence quality 判定機構も流用可 |
| **Attachment 制約付き MCS ＋ Tanimoto による Similar core 判定** | **L2 の core 類似度クラス** | **再構築コストが高い実装資産。0.1.11 の工夫をそのまま活かす。出力の仕方だけを変える** |
| Pixi による Skill 自己完結 | 全 Skill | 実行環境の分離として妥当 |
| Artifact 契約と監査の思想 | Phase 6 | 引用検証へ転用する |
| ローカル平坦性（cliff/SALI）計算 | L1/L3/L4 の土台 | ただし D002 限定から**全空間・近傍単位**へ一般化する |

既存Description Databaseはschema変換や一括再計算を行わず、同じProject rootとProgram名でin-place利用する。初回の0.2.1書込み前にwriter不在を確認し、SQLite backup APIで復旧可能なバックアップを作成する。互換性確認と本番Runの依頼文は正式プロンプト集3.2節および3.4節を使用する。
